# Contributing to the EtherNet/IP Receiver

User-facing documentation lives in [README.md](./README.md); design decisions
and the roadmap live in [DESIGN.md](./DESIGN.md).

## Prerequisites

- Go 1.25+
- [OpenTelemetry Collector Builder](https://opentelemetry.io/docs/collector/custom-collector/) (`ocb`) v0.152.0:

```bash
  go install go.opentelemetry.io/collector/cmd/builder@v0.152.0
```

- [`golangci-lint`](https://golangci-lint.run/) for `make lint`

> Version alignment: `ocb`, `otelcol_version` in `builder-config.yaml`, and the
> collector dependencies in `go.mod` must all match. This component currently
> targets ocb v0.152.0 with collector modules at v1.58.0 / v0.152.0.

## Make targets

```bash
make test    # run tests
make lint    # run golangci-lint
make build   # build ./bin/otelcol-ethernetip from builder-config.yaml
make run     # run the collector with ./config.yaml (requires build first)
make tidy    # tidy go modules
make clean   # remove build artifacts
```

## Running locally without hardware

The repository includes an EtherNet/IP simulator that serves a few tags
(`testtag`, `temperature`, `pumpstatus`) with slowly drifting values on the
standard EtherNet/IP ports (`0.0.0.0:44818` TCP, `0.0.0.0:2222` UDP):

```bash
# Terminal 1 — start the simulator
go run ./cmd/simulator

# Terminal 2 — build and run a collector pointed at it
cp config.example.yaml config.yaml
make build && make run
```

## Code generation

`metadata.yaml` is the source of truth for the component's status, metrics,
attributes and generated tests. After editing it, regenerate with `mdatagen`
at the same version as the collector dependencies:

```bash
git clone --depth=1 --branch v0.152.0 https://github.com/open-telemetry/opentelemetry-collector.git /tmp/otel-collector-mdatagen-src
(cd /tmp/otel-collector-mdatagen-src/cmd/mdatagen && go build -o "$(go env GOPATH)/bin/mdatagen" .)
go generate ./...
```

This rewrites `internal/metadata/`, `documentation.md`, the
`generated_*_test.go` files, and the status section at the top of
`README.md` (between the `<!-- status autogenerated section -->` markers).
Do not edit those parts by hand. Test-specific settings for the generated
tests, including the `goleak` ignores needed for the in-process `gologix`
test servers, are declared under `tests:` in `metadata.yaml`.

## Project layout

```
ethernetipreceiver/
├── config.go                # Config struct and validation
├── config_test.go           # Validate() tests and testdata/config.yaml loading tests
├── factory.go               # Component factory and default config
├── scraper.go               # Scrape loop and metric emission (lifecycle via scraperhelper)
├── client.go                # gologix client wrapper
├── client_test.go           # Integration tests against an in-process gologix.Server
├── scraper_test.go          # Scraper unit tests with a fake client
├── metadata.yaml            # mdatagen source of truth
├── documentation.md         # Generated metric documentation
├── generated_*_test.go      # Generated component and package tests
├── internal/metadata/       # Generated metrics builder and config
├── testdata/config.yaml     # Sample configurations used by config_test.go
├── cmd/simulator/           # EtherNet/IP simulator for local testing
├── config.example.yaml      # Example collector configuration
└── builder-config.yaml      # ocb manifest for the local test collector
```
