# Contributing to the Modbus Receiver

User-facing documentation lives in [README.md](./README.md); design decisions
and the roadmap live in [DESIGN.md](./DESIGN.md).

## Prerequisites

- Go 1.26+
- [OpenTelemetry Collector Builder](https://opentelemetry.io/docs/collector/custom-collector/) (`ocb`) v0.163.0:

```bash
  go install go.opentelemetry.io/collector/cmd/builder@v0.163.0
```

- [`golangci-lint`](https://golangci-lint.run/) for `make lint`

> Version alignment: `ocb`, `otelcol_version` in `builder-config.yaml`, and the
> collector dependencies in `go.mod` must all match. This component currently
> targets ocb v0.163.0 with collector modules at v1.69.0 / v0.163.0.

## Make targets

```bash
make test      # run tests
make lint      # run golangci-lint
make build     # build ./bin/otelcol-modbus from builder-config.yaml
make run       # run the collector with ./config.yaml (requires build first)
make simulate  # build and run the Modbus TCP simulator on localhost:5020
make tidy      # tidy go modules
make clean     # remove build artifacts
```

## Running locally without hardware

The repository includes a Modbus TCP simulator that serves fake sensor data
with slowly drifting values on `localhost:5020`. It uses a high port so it runs
without root; real devices use `502`.

| Address | Type | Data type | Value |
|---|---|---|---|
| 0-1 | holding register | `float32` | temperature (°C) |
| 2 | holding register | `uint16` | pressure (hPa) |
| 3 | holding register | `uint16` | humidity (%) |
| 4-5 | holding register | `float32` | flow rate (L/min) |
| 0 | coil | `bool` | pump status |
| 1 | coil | `bool` | valve status |

```bash
# Terminal 1 — start the simulator
make simulate

# Terminal 2 — build and run a collector pointed at it
cp config.example.yaml config.yaml
make build && make run
```

## Code generation

`metadata.yaml` is the source of truth for the component's status, metrics,
attributes and generated tests. After editing it, regenerate with `mdatagen`
at the same version as the collector dependencies:

```bash
git clone --depth=1 --branch v0.163.0 https://github.com/open-telemetry/opentelemetry-collector.git /tmp/otel-collector-mdatagen-src
(cd /tmp/otel-collector-mdatagen-src/cmd/mdatagen && go build -o "$(go env GOPATH)/bin/mdatagen" .)
go generate ./...
```

This rewrites `internal/metadata/`, `documentation.md`, the
`generated_*_test.go` files, and the status section at the top of
`README.md` (between the `<!-- status autogenerated section -->` markers).
Do not edit those parts by hand.

## Project layout

```
modbusreceiver/
├── config.go                # Config struct, register definitions and validation
├── config_test.go           # Validate() tests and testdata/config.yaml loading tests
├── factory.go               # Component factory and default config
├── receiver.go              # Lifecycle and poll loop
├── scraper.go               # Modbus TCP client, decoding and metric emission
├── scraper_test.go          # Scraper and receiver tests with a fake device
├── metadata.yaml            # mdatagen source of truth
├── documentation.md         # Generated metric documentation
├── generated_*_test.go      # Generated component and package tests
├── internal/metadata/       # Generated metadata and config
├── testdata/config.yaml     # Sample configurations used by config_test.go
├── cmd/simulator/           # Modbus TCP simulator for local testing
├── config.example.yaml      # Example collector configuration
└── builder-config.yaml      # ocb manifest for the local test collector
```

## Areas where contributions are especially welcome

- Device compatibility reports: byte order and data type findings for specific
  PLCs, meters and gateways.
- Modbus RTU/ASCII transport.
- Items from the [roadmap](./DESIGN.md#roadmap).
